Papaya — веб-сервис для школьников, где в одном месте собрана информация о всероссийских и региональных олимпиадах. Пользователи могут регистрироваться, управлять профилем и просматривать образовательные события.

## История изменений

### Текущая версия

- Аутентификация переведена на JWT в cookies доступа и обновления; регистрация и вход используют хеширование паролей и валидацию данных.
- Добавлены каталог активных олимпиад, страницы событий, список собственных событий, список пользователей и редактирование профиля.
- Пользователи с ролями `EDITOR` и `ADMIN` могут создавать и изменять события через интерфейс приложения.
- Реализован импорт олимпиад из PDF- и XLSX-таблиц. PDF обрабатываются Tesseract OCR в очереди Celery, а дополнительные столбцы таблицы сохраняются в описании события.
- Добавлены роли `USER`, `EDITOR` и `ADMIN`, а также отдельная панель администратора для управления пользователями и событиями.
- Приветственная страница и страницы входа и регистрации доступны без аутентификации.
- Добавлены кэширование в Redis и очередь Celery для ресурсоёмкой обработки PDF.
- Настроен контейнерный запуск всего окружения: PostgreSQL, Redis, веб-приложение, Celery и pgAdmin. `setup.sh` выполняется внутри контейнеров автоматически и проверяет Tesseract OCR.

## Скоро

- Роли школьника, студента, учителя и образовательной организации с разными возможностями.
- Категоризация олимпиад и распределение событий по вкладкам.
- Прямой импорт таблиц с фотографий в дополнение к PDF и XLSX.
- Расширение списка страниц, доступных без аутентификации.
- Отдельный улучшенный сценарий управления добавлением и изменением событий.
- Автоматизированные тесты.
- Вкладки олимпиад предоставляющие право поступления (бви) для определенного учебного заведения.
- Поиск.
- Теги олимпиад по их направлению.

## Стек технологий

- **Backend:** Python 3.11, FastAPI, Gunicorn, Uvicorn
- **Frontend:** HTML, CSS, JavaScript SPA, Tailwind CSS
- **База данных:** PostgreSQL 16, SQLAlchemy (async ORM), asyncpg
- **Аутентификация:** JWT в cookies, bcrypt, валидация Pydantic
- **Кэш и фоновые задачи:** Redis 7, Celery
- **Импорт таблиц:** pandas, OpenPyXL, img2table, Tesseract OCR
- **Контейнеризация:** Docker, Docker Compose

## Требования для запуска

Перед началом работы установите:

- **Git**;
- **Docker Desktop** либо Docker Engine;
- **Docker Compose v2** (команда `docker compose`);
- обеспечьте доступ к интернету для первой сборки образов и загрузки зависимостей.

Python, PostgreSQL, Redis и Tesseract отдельно устанавливать не нужно — они запускаются в Docker-контейнерах.

## Локальный запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/SHAMBALENOK/Papaya.git
cd Papaya
```

Запустите Docker Desktop, если используете его.

### 2. Настройка токенов

Перед первым запуском откройте `docker-compose.yml` и заполните поля `JWT_KEY` и `HF_TOKEN` в секциях `environment` сервисов `web` и `celery`:

```yaml
JWT_KEY: "ваш_длинный_случайный_секрет"
HF_TOKEN: "hf_ваш_токен_Hugging_Face"
```

Используйте одинаковые значения в обоих сервисах (Celery и Web):

- `JWT_KEY` — длинный случайный секрет для подписи JWT;
- `HF_TOKEN` — токен Hugging Face с правами на чтение, который можно создать на [странице настроек токенов](https://huggingface.co/settings/tokens).

Не публикуйте настоящие токены и не добавляйте их в коммиты публичного репозитория.

### 3. Сборка и запуск приложения

Из корня репозитория выполните:

```bash
docker compose up --build -d
```

Первая сборка может занять несколько минут: Docker загружает образы, Python-зависимости и компоненты OCR. Скрипт `setup.sh` является точкой входа контейнера и запускается автоматически — выполнять его вручную не нужно.

Проверьте состояние сервисов:

```bash
docker compose ps
```

После запуска доступны:

- приложение — [http://localhost:5000](http://localhost:5000);
- интерактивная документация API — [http://localhost:5000/docs](http://localhost:5000/docs);
- pgAdmin — [http://localhost:5050](http://localhost:5050).

Локальные данные pgAdmin из `docker-compose.yml`: логин `postgres@postgres.com`, пароль `postgres`. Для подключения к PostgreSQL из pgAdmin используйте хост `postgres`, порт `5432`, базу `postgres`, пользователя `postgres` и пароль `postgres`. Эти учётные данные предназначены только для локальной разработки.

Для просмотра логов веб-приложения и обработчика задач:

```bash
docker compose logs -f web celery
```

Чтобы вывести логи всех сервисов, выполните `docker compose logs -f`.

### 4. Остановка и очистка

Остановить сервисы, сохранив данные в Docker volumes:

```bash
docker compose down
```

Остановить сервисы и удалить тома PostgreSQL, Redis, pgAdmin и кэш моделей:

```bash
docker compose down -v
```

> [!WARNING]
> Команда с `-v` безвозвратно удалит локальную базу данных. Загруженные в `app/tables` файлы находятся в каталоге проекта и этой командой не удаляются.

## API и маршруты

Все API-маршруты используют префикс `/api/v1`. Полная интерактивная схема доступна в `/docs` после запуска приложения.

| Метод | Путь | Описание | Доступ |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/welcome` | Проверка сессии для публичной страницы | Публичный |
| `GET` | `/api/v1/auth/` | Состояние страницы авторизации | Публичный |
| `POST` | `/api/v1/auth/register` | Регистрация пользователя | Публичный |
| `POST` | `/api/v1/auth/login` | Вход и установка JWT cookies | Публичный |
| `GET` | `/api/v1/auth/logout` | Выход и удаление JWT cookies | Требуется вход |
| `GET` | `/api/v1/events/dashboard` | Каталог активных олимпиад | Требуется вход |
| `GET` | `/api/v1/events/dashboard/my_events` | События текущего пользователя | Требуется вход |
| `GET` | `/api/v1/events/<event_id>` | Данные события | Требуется вход |
| `POST` | `/api/v1/events/add_event` | Создание события | `EDITOR` или `ADMIN` |
| `POST` | `/api/v1/events/edit_event/<event_id>` | Изменение события | `EDITOR` или `ADMIN` |
| `POST` | `/api/v1/events/add_events_via_tables` | Импорт событий из PDF или XLSX | `EDITOR` или `ADMIN` |
| `GET` | `/api/v1/user/users` | Список активных пользователей | Требуется вход |
| `GET` | `/api/v1/user/<user_id>` | Профиль пользователя | Требуется вход |
| `POST` | `/api/v1/user/<user_id>/edit_info` | Изменение собственного профиля | Владелец профиля |
| `GET` | `/api/v1/admin/users` | Управление пользователями | `ADMIN` |
| `GET` | `/api/v1/admin/events` | Управление событиями и архивом | `ADMIN` |
