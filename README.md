## Коротко о сервисе

Papaya отвечает на один вопрос: **какие олимпиады дают льготу при поступлении в
нужный университет и на каких условиях?**

Сервис собирает официальные перечни олимпиад РСОШ, приказы и положения
университетов, а также сезоны и профили олимпиад, к которым эти документы
относятся. Школьнику не нужно перебирать сайты вузов и приказы: он находит свой
университет в каталоге, видит правила льгот по олимпиадам, сезонам и профилям,
открывает олимпиаду и переходит на её официальный сайт.

Продуктовая идея целиком описывается одной цепочкой:

```text
Олимпиада → сезон → профиль (уровень РСОШ)
          → правило льготы вуза → документ-основание
```

Всё, что не поддерживает эту цепочку, в Papaya сознательно не делается: ни
календаря олимпиад, ни расписания этапов, ни дедлайнов, ни рекомендательных
алгоритмов. Это агрегатор и каталог — не система поступления.

## Как это работает

| Роль | Что делает |
|------|-----------|
| **Школьник** (гость или зарегистрированный) | Ищет университет или олимпиаду, смотрит каталоги и страницы сущностей. Регистрация для этого не нужна. |
| **Представитель университета** | Управляет правилами льгот **своего** вуза: связывает существующие олимпиаду, сезон и профиль, указывает тип льготы, требуемый результат и документ-основание. Новые олимпиады, сезоны и профили не создаёт — может запросить отсутствующие. |
| **Администратор Papaya** | Ведёт каталог олимпиад и университетов, сезоны и профили, загружает документы РСОШ и подтверждает импорт, проверяет правила льгот, управляет пользователями, ролями и запросами представителей. |

Пользовательский сценарий целиком:

```text
Открыть Papaya
      ↓
Найти университет
      ↓
Открыть университет или отфильтровать каталог льгот
      ↓
Увидеть правила: олимпиада, сезон, профиль, уровень РСОШ, тип льготы
      ↓
Открыть олимпиаду и переключить актуальные и архивные сезоны
      ↓
Прочитать документ-основание и перейти на официальный сайт
```

## Быстрый запуск

Нужны только Docker Desktop (или Docker Engine) и Docker Compose v2 — Python,
PostgreSQL, Tesseract и остальные зависимости ставятся в контейнерах.

```bash
git clone https://github.com/SHAMBALENOK/Papaya.git
cd Papaya
cp .env.example .env
# замените JWT_KEY в .env на собственный случайный секрет:
python -c "import secrets; print(secrets.token_hex(32))"
docker compose up -d --build
```

После запуска:

- приложение — http://localhost:5000
- интерактивная документация API — http://localhost:5000/docs
- pgAdmin — http://localhost:5050 (логин `postgres@postgres.com`, пароль
  `postgres`; хост `postgres`, порт `5432`, база `postgres`)

Переменные окружения, порты, сборка образа, логи и остановка —
в [docs/getting-started.md](docs/getting-started.md).
