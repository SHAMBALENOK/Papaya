# 🥭 Papaya — что уже сделано и что дальше

> Документ описывает состояние проекта **после** перехода к канонической модели
> MVP: олимпиада → сезон → профиль → правило льготы → документ-основание.
> Исторических планов здесь нет: старые идеи (календарь олимпиад, этапы и даты,
> отдельная заявка БВИ, справочник источников, ML-рекомендации, трекер участия)
> в текущем этапе сознательно не реализуются.

## Продуктовая концепция (зафиксирована)

> **«Какие олимпиады дают льготу при поступлении в нужный мне университет и на
> каких условиях?»**

```text
Олимпиада → сезон → профиль (уровень РСОШ)
          → правило льготы вуза → документ-основание
```

Papaya — агрегатор: каталог университетов, каталог олимпиад с сезонами и
профилями, правила льгот, опубликованные университетами, и импорт официальных
перечней РСОШ. Это не система поступления, не календарь олимпиад и не
социальная сеть.

## Текущий этап — MVP канонической модели

### Доменная модель

- [x] `universities` — каталог университетов: полное название, краткое название,
      описание, официальный сайт, две картинки (`preview_image` для карточек и
      `image` для страницы), нормализованное имя (защита от дублей).
- [x] `olympiads` — единый каталог олимпиад: название, описание, официальный
      сайт, две картинки, организатор свободным текстом (`organizer`), статус
      актуальности (`PUBLISHED` / `ARCHIVED`), причина архива
      (`RSOSH_ABSENT` / `MANUAL`), документ-источник. Уровня РСОШ у олимпиады
      нет: он принадлежит профилю сезона.
- [x] `olympiad_seasons` — сезон: олимпиада + метка года (`season_label`) и
      версия. Дат регистрации/проведения и флага `availability` нет.
- [x] `season_profiles` — профиль сезона: название, уровень РСОШ
      (`1` / `2` / `3` / `null`) и версия. Уровень не переносится между
      сезонами.
- [x] `benefit_rules` — правило льготы: университет, олимпиада, сезон, профиль,
      тип льготы (`BVI` / `EGE_100` / `DVI_100` / `OTHER`), требуемый результат
      (`WINNER` / `PRIZE` / `WINNER_OR_PRIZE`), документ-основание, статус
      проверки, публикация и версия.
- [x] `benefit_ege_requirements` — необязательное требование ЕГЭ правила:
      предмет и минимальный балл. Отдельная структура, не поле профиля.
- [x] `university_programs` — самостоятельный справочник образовательных
      программ вуза. С правилами льгот не связан.
- [x] `entity_requests` — запрос представителя на отсутствующие олимпиаду, сезон
      или профиль: тип, название, родительская сущность, статус и причина отказа.
- [x] `docs` — документы двух видов: `RSOSH_LIST` (перечень, привязан к импорту)
      и `UNIVERSITY_ORDER` / `OTHER` (документ вуза, основание правила). Файл,
      название, контрольная сумма, состояние обработки, `metadata['rsosh']` и
      единственное поле ссылки на оригинал `source_url`.
- [x] `users.university_id` — привязка представителя университета.
- [x] Инвариант роли: `EDITOR` невозможен без университета — проверка в
      приложении и CHECK-ограничение в БД (миграция `0006`).
- [x] Единственный способ сменить роль вместе с привязкой:
      `POST /api/v1/admin/role/{id}`.
- [x] Валидация ссылок каталога (`website`, `official_url`, `preview_image`,
      `image`): только `http`/`https`, `javascript:`/`data:`/`file:` и строки без
      схемы отклоняются.
- [x] Удалены отдельная сущность источника, отдельная заявка и раздел модерации
      БВИ, параллельная сущность БВИ, даты сезона, `availability`, свободный
      текст результата и смешанные «дополнительные требования».
- [x] Легаси-таблицы снесены миграцией `0016` после переноса данных и проверки
      целостности; сырые значения сохранены в архивной таблице миграции.
- [x] Физического удаления каталога нет нигде: олимпиада и университет только
      архивируются, чтобы не разрушать правила и документ-основание.

### Каталоги и поиск

- [x] Публичные каталоги университетов и олимпиад с карточками.
- [x] Поиск по названию, краткому названию, описанию (регистронезависимо,
      переносы строк в ячейках не мешают).
- [x] Единый поиск по обоим каталогам `GET /api/v1/search`.
- [x] Страницы университета и олимпиады; связи строятся по правилам льгот.
- [x] Комбинируемые серверные фильтры каталога льгот: вуз, олимпиада, тип,
      предмет/профиль, программа, сезон, уровень РСОШ и поиск.
- [x] Пагинация с фильтрами и корректный `total` (без загрузки всего каталога).
- [x] Программы зависят от вуза и фильтруются в его контексте; фильтры есть и
      на странице вуза.
- [x] Страница олимпиады: сезоны, профили выбранного сезона, уровень РСОШ в
      контексте профиля, льготы выбранного сезона и официальные ссылки.
- [x] Переключение актуальных и архивных сезонов; данные разных сезонов не
      смешиваются, архив сохраняет профили и правила.
- [x] Публичный источник данных олимпиады `GET /api/v1/olympiads/{id}/source`:
      всегда `200`, ровно два пользовательских поля (`title`, `has_file`),
      внутренний `source_doc_id` публично не отдаётся.
- [x] Краткое название выше полного в карточках, каталоге и заголовках страниц;
      полное название не прячется.
- [x] На главной университеты — главный раздел, олимпиады — вторичный.

### Правила льгот

- [x] БВИ создаётся и редактируется только как обычное правило
      (`benefit_type: "BVI"`); отдельной формы и процесса заявки нет.
- [x] Ссылки правила проверяются на сервере: сезон принадлежит олимпиаде,
      профиль — сезону, документ — тому же вузу; иначе `422`.
- [x] Созданное правило всегда `unverified`: статус проверки из клиента
      игнорируется.
- [x] Представитель управляет правилами только своего вуза (object-level
      проверка на каждом изменяющем маршруте); администратор — любого.
- [x] Публичная выдача: `is_published = true` и статус не `rejected`.
      Непроверенное правило видно с пометкой «Не проверено Papaya»; черновик и
      отклонённое правило не видны даже по прямому id.
- [x] Проверка — только администратором и только по приказу/положению вуза
      (`UNIVERSITY_ORDER`) того же университета.
- [x] Отклонение требует непустой причины и снимает правило с публикации.
- [x] Оптимистичная блокировка: правка передаёт `version`, устаревшая даёт
      `409`; проверка и запись — под `FOR UPDATE`.
- [x] Откат принимает номер целевой версии и ожидаемую текущую, атомарен,
      создаёт новую версию, ставит `unverified` и пишет
      `BenefitStatusHistory`; проверяет существование и принадлежность
      программ, сезонов, профилей и документов.
- [x] Аналогичная защита версий у сезонов и программ.
- [x] Неполные правила из legacy BVI не удалены: помечены `needs_review` и
      стоят в админской очереди «Заполнить сезон и профиль».
- [x] `is_published` — отдельный тумблер представителя: скрытие из каталога не
      снимает `verified`.

### Кабинет представителя и админка

- [x] CRUD правил своего вуза с привязкой к олимпиадам, сезонам и профилям.
- [x] Управление программами и документами своего вуза.
- [x] Публикация и снятие правила с публикации.
- [x] История версий, история статусов и восстановление версии.
- [x] Запрос отсутствующих олимпиад, сезонов и профилей; очередь в админке,
      проверка дублей при одобрении и `409` при повторном одобрении.
- [x] Админка: полное управление всеми сущностями, поиск, фильтры, серверная
      пагинация и `total`, связанные сущности и состояния.
- [x] Модерация льгот с причиной отказа, документом-основанием, автором и
      историей. Отдельных разделов BVI и источников нет.
- [x] Аудит действий пользователей и администраторов; ошибки записи аудита
      логируются, но не роняют основную операцию.
- [x] Защита от потери доступа: последнего активного администратора нельзя
      заблокировать или понизить (`409`), проверка атомарна.

### Импорт РСОШ

- [x] XLSX: нативное чтение ячеек, многострочные и объединённые ячейки.
- [x] PDF с текстовым слоем: разбор структуры документа.
- [x] Сканы и изображения: предобработка, OCR (Tesseract `rus+eng`).
- [x] Определение ориентации страницы (OSD + сравнительный OCR) и наклона.
- [x] Реконструкция таблиц по геометрии, многостраничные таблицы.
- [x] Нормализация ячеек, зеркальная шапка РСОШ, отбрасывание служебных строк.
- [x] Валидация и оценка качества распознавания по страницам.
- [x] Дедупликация: точное совпадение, близкое совпадение, пометка сомнительных
      записей для проверки.
- [x] Preview, частичное подтверждение (`skip`), отклонение результатов.
- [x] Повторный импорт не создаёт дублей и не переносит даты/профили между
      сезонами.
- [x] Импорт не создаёт подтверждённые правила: он меняет только актуальность
      олимпиад.
- [x] Ошибка распознавания не маскируется под успех; снятый в preview кандидат
      не архивирует существующую олимпиаду.
- [x] Архивирование олимпиад, исчезнувших из перечня РСОШ, с причиной
      `RSOSH_ABSENT`; ручной архив — `MANUAL`.
- [x] Фоновый запуск в Celery с fallback на выполнение в процессе API.
- [x] Журнал запусков импорта: кто и когда запустил, чем закончилось,
      построчные результаты подтверждения.

### Официальный перечень (сканы 86–200 страниц)

- [x] Отдельный режим для скана официального перечня: таблица и учебный год
      распознаны в документе; остальные документы идут прежним конвейером.
- [x] Таблица XLSX строится до сопоставления: лист «Перечень <сезон>» с шапкой
      конкретного года и лист «Сводка», агрегированный из первого листа.
- [x] HTML-версия таблицы и производные документы `RSOSH_TABLE` / `RSOSH_HTML`;
      файлы хранятся на сервере под UUID-именем.
- [x] План импорта: создание и использование записей, сезоны, профили, уровни,
      отсутствующие, дубли и ошибки; правка плана администратором.
- [x] Атомарное применение плана под блокировкой перечней, отказ от повторного
      применения, история решений в метаданных документа.
- [x] Админ-интерфейс: загрузка, ход обработки, таблица и XLSX, сопоставление,
      проверка, подтверждение, история; серверная пагинация таблицы.
- [x] Тесты: извлечение из разных сканов, XLSX и сводка, сезоны, отсутствующие,
      повторный импорт, откат, права; сверка с эталоном по содержанию.

### Инфраструктура и качество

- [x] Alembic-миграции, применяемые при старте; `ensure_db_schema.py` создаёт
      отсутствующую базу.
- [x] Версионный кэш профилей в Redis; каталоги читаются из PostgreSQL.
- [x] Health/readiness-маршруты, Docker healthcheck.
- [x] Автотесты: бизнес-логика, роли, все форматы импорта, дедупликация,
      архивирование, гонки, версии и откат.
- [x] Безопасная загрузка и скачивание документов: размер, сигнатура, формат,
      защита от path traversal.
- [x] Корректные `401` / `403` / `404` / `409` / `422`; SPA работает после
      обновления страницы.
- [x] Светлая дизайн-система: белый фон, зелёный бренд, Inter для текста,
      Manrope для заголовков, SVG-знак Papaya, статусы словами, Toast и нижняя
      мобильная навигация.
- [x] Документация: `README.md`, `MVP.md`, `docs/responses.md`, `English.md`
      соответствуют схеме API.

## Следующие шаги (после MVP)

Приоритеты — от наибольшей пользы для сценария к меньшей.

### P0 — качество данных каталога

- [ ] Массовое обновление официальных сайтов олимпиад (сейчас заполняется
      вручную) — через импорт поля «ссылка», если оно появится в документах.
- [ ] Разовый прогон импорта актуального перечня РСОШ с подтверждением для
      первичного наполнения сезонов и профилей.
- [ ] Подсказки администратору при разборе очереди `needs_review`: какие
      сезоны и профили подходят к олимпиаде правила.

### P1 — качество использования

- [ ] Поиск с подсказками и ранжированием (частотность запросов, `pg_trgm`).
- [ ] Обзор «олимпиады, которые дают льготу в N университетах» по направлениям
      без новых сущностей.
- [ ] Производные счётчики льгот на карточках (из опубликованных правил).
- [ ] Экспорт списка правил университета (CSV/PDF) для внутреннего
      использования вузами.
- [ ] Сравнение правил двух сезонов одной олимпиады.

### P2 — эксплуатация

- [ ] Rate limiting и security headers на публичных маршрутах.
- [ ] Структурированные логи и метрики импорта (длительность, страницы,
      уверенность распознавания).
- [ ] Проверка CORS/CSRF и полное описание OpenAPI.
- [x] CI: прогон тестов и `node --check` на каждый push
      (`.github/workflows/tests.yml`).

### Отложено осознанно

Не входит в текущий этап и не планируется без отдельного решения:
календарь и этапы олимпиад, даты и дедлайны, результаты, факультеты,
школы, избранное, рекомендации (в том числе ML), личный трекер участия,
мобильное приложение, социальные функции, платежи.

> Слово «приобрести» в интерфейсе — пользовательская терминология: сервис
> не продаёт и не принимает оплату, он фиксирует правило «университет даёт
> льготу за олимпиаду на таких условиях».
