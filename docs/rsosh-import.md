# Импорт документов РСОШ

[← Документация](README.md) · [К README проекта](../README.md) · [English](en/rsosh-import.md)

Олимпиада попадает в каталог **двумя способами** и только двумя:

1. **Импорт официального документа РСОШ** — основной путь.
2. **Ручное создание администратором** — резервный путь.

Массовый импорт «произвольных таблиц» (бывший
`POST /api/v1/events/add_events_via_tables`) в проекте отсутствует: ни маршрута,
ни кода, ни кнопки в интерфейсе.

## Pipeline

```text
Document
    ↓ определение типа файла (сигнатура, не только расширение)
Предобработка растра + определение ориентации (0/90/180/270)
    ↓
Извлечение: нативное чтение XLSX → таблицы PDF с текстовым слоем → OCR скана/изображения
    ↓
Детекция и реконструкция таблиц (линии рамки, объединённые и многострочные ячейки)
    ↓
Нормализация ячеек (переносы строк, кавычки, «ё», зеркальная шапка РСОШ)
    ↓
Извлечение олимпиад (поиск колонки с названием, отбрасывание служебных строк)
    ↓
Валидация (длина названия, мусор, уверенность распознавания)
    ↓
Дедупликация: точное совпадение → merge, близкое → merge, сомнительное → на проверку
    ↓
Импорт preview (ничего не записано)
    ↓ подтверждение администратором
Создание/обновление олимпиад + архивирование исчезнувших из перечня
```

Особенности, которые учитывает импортёр:

- **XLSX** читается нативно (openpyxl): многострочные ячейки, объединённые по
  вертикали диапазоны, несколько листов;
- **PDF с текстовым слоем** разбирается по структуре документа (pdfplumber), OCR
  не применяется зря;
- **скан без текстового слоя** рендерится в растр (300 dpi) и распознаётся
  Tesseract (`rus+eng`) с передачей координат слов;
- **повёрнутые страницы** (90/180/270) определяются через OSD Tesseract, при
  отказе OSD — сравнительным распознаванием кандидатов;
- **«заваленные» страницы** выпрямляются по оценке наклона;
- **таблица на нескольких страницах** собирается в одну, повтор шапки
  отбрасывается, шапка первой страницы используется для всех следующих;
- **зеркально отрисованная шапка** (особенность части документов РСОШ)
  распознаётся и разворачивается;
- **служебные строки** (шапка письма, реквизиты приказа, подписи) в каталог не
  попадают;
- **пустой или нечитаемый документ** не импортируется молча: в статусе
  появляется `failed` с понятной причиной.

## Состояние прогона

Состояние хранится в `docs.metadata['rsosh']` (`processing` / `paused` /
`review` / `approved` / `rejected` / `failed`) — отдельная таблица прогонов не
нужна, потому что прогон всегда относится к конкретному документу.

Пока прогон в `processing`, в разделе есть стадия `progress` (`starting` /
`extracting` / `matching`), поэтому панель показывает, что происходит, а не
голое «обрабатывается». Администратор может поставить прогон на паузу и
продолжить позже: пауза срабатывает на границе стадии, а если она наступила
после распознавания, распознанные строки сохраняются и продолжение идёт сразу к
сопоставлению без повторного чтения документа. Выбор администратора при
проверке (подтверждённые/снятые кандидаты, переименования, принудительные
объединения) сохраняется вместе с прогоном, переживает перезагрузку страницы и
применяется при подтверждении, если тело запроса не передано.

Запуск по умолчанию — фоновая задача Celery
(`python -m app.rsosh.worker_run <doc_id>`), с автоматическим переходом на
выполнение в процессе API, если брокер недоступен
(`RSOSH_EXECUTION=auto|celery|inline`).

## Официальный перечень: таблица → план → применение

Скан, распознанный как официальный перечень РСОШ (найдена таблица и прочитан
учебный год), идёт своим конвейером; остальные документы продолжают работать по
прежней схеме `preview` + `confirm`. Режим виден в состоянии импорта как
`mode: "official_list"`.

```text
PDF сохраняется под UUID-именем
    ↓ фоновая задача Celery (RSOSH_EXECUTION=auto|celery|inline)
Распознавание: ориентация страниц, линии таблицы, повтор шапки, объединённые и многострочные ячейки
    ↓
XLSX («Перечень <сезон>» + «Сводка») и HTML-версия
    ↓ производные документы RSOSH_TABLE / RSOSH_HTML, файлы только на сервере
План импорта: создать / использовать / требует решения / пропустить, с сезонами, профилями, уровнями и отсутствующими
    ↓ администратор правит план (PATCH …/plan)
Применение одной транзакцией (POST …/apply) — документ применяется один раз
    ↓
Записи ImportJob/ImportRecord и история решений в docs.metadata['rsosh']
```

Правила конвейера:

- **Таблица появляется до сопоставления.** XLSX — промежуточный артефакт, а не
  отчёт: план строится по нему. Лист 1 — перечень, лист 2 — сводка,
  агрегированная из листа 1.
- **Сезон берётся из документа**, а не из года запуска импорта. Профили и уровни
  принадлежат сезону, поэтому олимпиада не дублируется между сезонами, а смена
  уровня попадает в историю.
- **Нечёткие совпадения не применяются автоматически.** Точное совпадение
  нормализованного названия даёт `use`, похожие записи — `review` и требуют
  решения администратора.
- **Нераспознанная строка — ошибка, а не тишина.** Пока профиль или уровень не
  заполнен, `apply` заблокирован; пропустить строку можно только явным действием
  `action: "skip"`.
- **Отсутствующие олимпиады не удаляются.** Отсутствие фиксируется только по
  полному перечню (`complete=true`, есть сезон, нет нерешённых ошибок,
  `missing_allowed=true`) и только по запросу (`mark_missing=true`): профили
  теряют уровень, олимпиады уходят в архив с причиной `RSOSH_ABSENT`.
- **Повторный разбор того же документа ничего не дублирует.** Таблица и HTML
  переиспользуются, план пересобирается, повторное применение возвращает `409`.
- **Применение атомарно.** Одна транзакция под блокировкой применения перечней;
  при ошибке откатывается всё.

Страница документов показывает исходный PDF, сгенерированный XLSX, HTML-таблицу,
сезон, дату, статус и автора. Сама таблица листается на сервере
(`GET …/table` с `sheet`, `offset`, `limit`, `search`): в перечне 300+ строк.

## API импорта

| Маршрут | Назначение |
|---------|-----------|
| `POST /api/v1/docs/upload` | загрузить документ-источник (`type=RSOSH_LIST`, `UNIVERSITY_ORDER`, `OTHER`) |
| `POST /api/v1/imports/rsosh` | запустить импорт документа |
| `GET /api/v1/imports` | список прогонов импорта |
| `GET /api/v1/imports/{id}` | состояние, сводка и предупреждения |
| `GET /api/v1/imports/{id}/preview` | кандидаты: что будет создано, что обновлено, что требует проверки |
| `POST /api/v1/imports/{id}/confirm` | применить импорт (`skip` — исключённые `name_norm`, `archive_missing`) |
| `POST /api/v1/imports/{id}/reject` | отклонить результаты, ничего не записав |
| `POST /api/v1/imports/{id}/pause` | поставить прогон на паузу |
| `POST /api/v1/imports/{id}/resume` | продолжить приостановленный прогон |
| `PUT /api/v1/imports/{id}/selection` | сохранить выбор администратора при проверке |
| `GET /api/v1/imports/{id}/plan` | план импорта официального перечня (ничего не записано) |
| `PATCH /api/v1/imports/{id}/plan` | исправить сопоставление, название, уровень или действие |
| `POST /api/v1/imports/{id}/apply` | применить утверждённый план атомарно |
| `GET /api/v1/imports/{id}/history` | что документ изменил в каталоге |
| `GET /api/v1/imports/{id}/table` | постраничный просмотр таблицы перечня или сводки |

См. также: [модель данных](data-model.md) · [API](api.md) ·
[архитектура](architecture.md).
