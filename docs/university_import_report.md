# Импорт приказов университетов — отчёт этапа 2 (ветка `patch-0.10`)

> Этап 2 отвечает на вопрос: **как из приказа вуза получить связи БВИ**.
> Отчёт фиксирует, что сделано, какие решения приняты и какие метрики получены
> на реальном документе. Измерения воспроизводимы скриптами в `scripts/`.

## Постановка

Импорт приказа университета — **отдельный адаптер** (`app/university/`), а не
расширение импорта РСОШ. Причина в разной природе документов:

| | Перечень РСОШ | Приказ вуза |
| --- | --- | --- |
| Что создаёт | олимпиады каталога | заявки БВИ на существующие олимпиады |
| Источник строк | сам документ | каталог олимпиад |
| Архивация | олимпиады, исчезнувшие из перечня | нет |
| Подтверждение | создание/обновление каталога | только `PENDING`-связи |

Главный инвариант: **приказ не создаёт олимпиад**. Строка приказа либо
сопоставляется с существующей олимпиадой каталога, либо остаётся без пары и
связывается администратором вручную. Никаких автоподтверждений: импорт пишет
только заявки `PENDING`, подтверждает их модератор отдельным действием.

## Что сделано

### Ядро адаптера (`app/university/`)

- `types.py` — `UniversityRecord` (строка приказа + `meta`: направление,
  профиль, предмет, уровень, диплом), `UniversityCandidate` (строка после
  сопоставления: `olympiad_id`, `match_score`, `confidence`), `PageReport`,
  `UniversityError`/`UniversityConflictError`.
- `parsing.py` — разбор приказа: определение колонок по синонимам заголовков,
  память шапки и колонки названия по ширине таблицы (шапка печатается только на
  первой странице), раздача объединённой ячейки направления вниз, двойное
  прочтение зеркальных ячеек. Вуз берётся из **шапки письма** (короткая таблица
  с «Министерство …» и наименованием в скобках), а не из названий олимпиад.
- `matching.py` — сопоставление строк с каталогом: делегирует в общее ядро
  `app.rsosh.matching.best_catalog_match`, схлопывает дубли по `name_norm`.
- `states.py` — раздел `docs.metadata['university']` (состояние, этапы, сводка,
  кандидаты, выбор администратора, провенанс).
- `persist.py` — запись в **отдельной транзакции**: `apply_confirmed_import`
  (в SAVEPOINT на каждого кандидата; `_upsert_link` пишет только `PENDING`);
  пауза/возобновление/отклонение под advisory-блокировкой.
- `processor.py` — оркестратор `run_import`/`confirm_import`
  (с контрольной точкой по записям и проверками паузы на границах этапов),
  запуск через Celery с fallback на inline.
- `worker.py`/`worker_run.py` — фоновая задача `papaya.university.import`.

### Модель и провенанс

- Миграция `0011_bvi_source_provenance.py` (идемпотентная): у связи
  `university_olympiads` добавлены `source_doc_id UUID` (FK → `docs(id)`
  `ON DELETE SET NULL`) и `source_meta JSONB` — аддитивно, без изменения
  существующих полей. `source_meta` хранит провенанс: направление, профиль,
  уровень, диплом из строки приказа.
- Серializer связи (`app/middlewares/serializers.py::bvi_link_to_dict`) отдаёт
  новые поля.

### HTTP-слой (`app/routers/imports.py`)

Отдельные маршруты (`/api/v1/imports/university*`), чтобы не смешивать с РСОШ:

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/imports/university` | начать импорт приказа |
| `GET` | `/imports/university` | список прогонов приказов |
| `GET` | `/imports/university/{id}` | статус прогона |
| `GET` | `/imports/university/{id}/preview` | строки, распознанный вуз, кандидаты |
| `PUT` | `/imports/university/{id}/selection` | сохранить выбор администратора |
| `POST` | `/imports/university/{id}/confirm` | создать заявки БВИ (`PENDING`) |
| `POST` | `/imports/university/{id}/reject` | отклонить результаты |
| `POST` | `/imports/university/{id}/pause` | приостановить обработку |
| `POST` | `/imports/university/{id}/resume` | возобновить обработку |

Роут приказа не отдаёт прогон РСОШ (404) и наоборот — типы документов строго
разделены. `UniversityConflictError` → 409, `UniversityError` → 400.

### Интерфейс

- `api.js` — методы `listUniversityImports`, `startUniversityImport`,
  `universityImportPreview`, `confirmUniversityImport`, `rejectUniversityImport`,
  `pauseUniversityImport`, `resumeUniversityImport`, `saveUniversitySelection`.
- `admin.js` — вкладка **«Приказы вузов»** (`#/admin/orders`): список прогонов,
  загрузка приказа (тип документа `UNIVERSITY_ORDER`), меню проверки
  (`#/admin/orders/{id}`). В меню проверки: выбор вуза (подтверждение или
  переопределение распознанного), связывание строк с каталогом, пропуск строк,
  поиск. **Правки названий и объединений отсутствуют** — приказ не создаёт
  олимпиад.
- `router.js` — маршрутизация `#/admin/orders/{id}`.

### Тесты

- `tests/test_university_parsing.py` (11) — разбор приказа: шапка письма ≠
  строка, память шапки между страницами, раздача merged-направления,
  предмет ≠ диплом, зеркальная шапка, отсутствие слова «олимпиада», вуз не из
  названия олимпиады, реальный PDF ИТМО.
- `tests/test_university_import.py` (11) — preview не пишет, confirm создаёт
  только `PENDING`, провенанс в `source_meta`, идемпотентность, confirm без
  вуза → ошибка, reject не трогает каталог, документ РСОШ не импортируется
  вузовским адаптером, сквозной HTTP-цикл, разделение типов в роутах.
- Полный прогон: **350 passed**.

## Измерения

Методика: `python scripts/university_baseline.py <pdf> --json out.json`. Скрипт
не трогает базу — только извлекает страницы и разбирает приказ, повторяя
боевой `processor.run_import`. Эталонной размеченной выборки нет (вузовский
документ один), поэтому метрики описывают **сам факт разбора**, а не точность
сопоставления с эталоном.

Документ: `app/tables/rsosh_bvi/rsosh_bvi.pdf` (приказ ИТМО, 10 страниц, PDF с
текстовым слоем).

| Метрика | Значение |
| --- | --- |
| Страниц | 10 |
| Время извлечения | 4.2 с |
| Время разбора | 0.1 с |
| Распознанный вуз | «Университет ИТМО» (`name_norm`: `университет итмо`) |
| Строк приказа | 54 |
| Уникальных олимпиад | 31 |
| Страниц со строками | 10 из 10 |
| Средняя уверенность чтения | 1.0 |
| Строк без направления | 29 |
| Строк без слова «олимпиада» | 2 |
| Предупреждений | 11 |

Предупреждения: 10 «олимпиада встречается несколько раз» (повторы направления
по строкам — связь создаётся одна) и 1 «2 записи без слова „олимпиада“ —
требуют проверки».

### Известные ограничения разбора (уровень проверки, не ошибка)

- 29 из 54 строк без `direction`: объединённая ячейка направления начинается на
  странице 1 и не переносится через разрыв страницы. Строка остаётся валидной
  (олимпиада, уровень, диплом на месте), но направление нужно смотреть глазами.
- 2 строки без слова «олимпиада» — «Турнир городов» и «Олимпиада школьников
  «Ломоносов»»-подобные названия помечены и требуют внимания модератора.
- Вуз определяется только из шапки письма: если у документа другой шаблон
  шапки, вуз не распознается — администратор выбирает его вручную в меню.

## Ограничения задачи (соблюдены)

- Не переписывать проект: адаптер добавлен рядом с РСОШ, общий код вынесен в
  `app.rsosh.matching.best_catalog_match`.
- Не создавать параллельный импортёр: переиспользованы `extraction`, `tables`,
  `normalization` РСОШ.
- Не менять модель/API без совместимости: миграция `0011` аддитивная.
- Не обходить модерацию: импорт пишет только `PENDING`, подтверждает модератор.
- Не подгонять результаты: метрики сняты с реального документа как есть.

## Продолжение: MVP-расширение (ТЗ)

Этап 3 развивает модель, заложенную этапом 2. Приказ вуза по-прежнему создаёт
только `PENDING`-связи, но у самой связи теперь есть правило льготы, версии и
история, а у вуза — заявка на роль представителя.

| Что | Где |
| --- | --- |
| Вид льготы, проверка, подтверждение вуза | `app/models/bvi.py`, `app/database/bvi.py` |
| Версии правила и откат | `app/models/benefit_versions.py`, `app/database/bvi.py` |
| Сезоны и профили олимпиады | `app/models/seasons.py`, `app/database/seasons.py` |
| Образовательные программы вуза | `app/models/programs.py`, `app/database/programs.py` |
| Заявки представителя | `app/models/applications.py`, `app/database/applications.py` |
| Доступность документа-источника | `app/models/docs.py`, `app/database/docs.py` |
| Миграция | `migrations/versions/0012_mvp_benefits_seasons_applications.py` (аддитивная, `down_revision = '0011'`) |
| Новые маршруты | `app/routers/universities.py` (правила льгот, программы), `app/routers/olympiads.py` (сезоны), `app/routers/applications.py` (заявки), `app/routers/docs.py` (доступность) |
| Тесты | `tests/test_mvp_benefits.py` — 24 теста |

Инварианты, которые перенесены из этапа 2 без изменений:

- импорт приказа не создаёт олимпиады и не выдаёт прав;
- роль представителя выдаётся только через защищённый путь `apply_role_guarded`;
- назначение роли и запись о решении по заявке — одна транзакция: если роль
  выдать нельзя, заявка остаётся в ожидании;
- физического удаления каталога нет: отзыв подтверждения удаляет связь, но не
  трогает историю версий.

Проверки: полный набор тестов — **374 passed** (было 350 до MVP-расширения).
