# Модель данных

[← Документация](README.md) · [К README проекта](../README.md) · [English](en/data-model.md)

```text
Olympiad ── Season ── Profile (уровень РСОШ 1/2/3 или пусто)
    │           │                │
    └──── Benefit rule ──────────┘
                 │
        Документ вуза (docs)
```

| Таблица | Что хранит |
|---------|-----------|
| `users` | Профиль, роль (`USER` / `EDITOR` / `ADMIN`), привязка представителя к университету (`university_id`) и признак активности (`isActive`): заблокированный администратор не считается администратором. |
| `universities` | Университет: полное название, краткое название, описание, официальный сайт, две картинки (`preview_image` для карточек и `image` для страницы), нормализованное имя для защиты от дублей. |
| `olympiads` | Олимпиада: название, описание, официальный сайт, две картинки, организатор, статус актуальности (`PUBLISHED` / `ARCHIVED`), причина архива (`RSOSH_ABSENT` / `MANUAL`), документ-источник. Уровня РСОШ у олимпиады нет. |
| `olympiad_seasons` | Сезон олимпиады: `season_label` и версия. Дат регистрации/проведения и флага доступности нет. Архивный сезон сохраняет профили и правила. |
| `season_profiles` | Профиль сезона: название и уровень РСОШ (`1` / `2` / `3` / `null`). Уровень принадлежит конкретному профилю конкретного сезона и не переносится на другой сезон. |
| `benefit_rules` | Правило льготы: университет, олимпиада, сезон, профиль, тип льготы (`BVI` / `EGE_100` / `DVI_100` / `OTHER`), требуемый результат (`WINNER` / `PRIZE` / `WINNER_OR_PRIZE`), документ-основание, статус проверки, публикация и версия. |
| `benefit_ege_requirements` | Необязательное требование ЕГЭ правила: предмет и минимальный балл. Отдельная структура, не поле профиля. |
| `university_programs` | Образовательные программы вуза — самостоятельный справочник. С правилами льгот не связан. |
| `entity_requests` | Запрос представителя на отсутствующие олимпиаду, сезон или профиль: тип, название, родительская сущность, статус и причина отказа. |
| `docs` | Документ: `RSOSH_LIST` (перечень, привязан к импорту) или `UNIVERSITY_ORDER` / `OTHER` (документ вуза, основание правила). Файл, название, контрольная сумма, состояние обработки и `metadata['rsosh']` с состоянием прогона. |

## Ключевые решения

- **Олимпиада — единая каноническая сущность.** Записей «олимпиада 2026» и «олимпиада 2027» в каталоге нет: одна запись на олимпиаду независимо от года. Год живёт в сезоне.
- **Сезон — это олимпиада и метка.** Дат регистрации/проведения и доступности у сезона нет: это состояние приёмной кампании вуза, а не свойство олимпиады.
- **Уровень РСОШ принадлежит профилю сезона.** Допустимы `1`, `2`, `3` или пусто; уровень не копируется в другой сезон, потому что набор профилей и уровни меняются каждый год.
- **Правило льготы — единственное место, где заявлена льгота.** Оно связывает вуз, олимпиаду, сезон и профиль, тип льготы и требуемый результат с документом-основанием. БВИ — это `benefit_type: "BVI"`, отдельной сущности, заявки и раздела модерации БВИ нет.
- **Требование ЕГЭ — отдельная необязательная структура.** `{"subject", "min_score"}` привязано к правилу, а не к профилю олимпиады.
- **Связи правила проверяются.** Сезон обязан принадлежать олимпиаде, профиль — сезону, документ — тому же вузу; иначе `422`. Архивная олимпиада не принимает новых правил, но существующие остаются доступными и редактируемыми.
- **Не удалять, а архивировать.** У олимпиады есть история: правила льгот, документ-источник, путь по перечню РСОШ. Физического удаления каталога в системе нет вообще — ни в слое данных, ни в API.
- **Причина архива — обязательна.** Статус один, а решение принимают два механизма, поэтому у архивной записи есть причина: `RSOSH_ABSENT` (нет в перечне РСОШ — вернёт импорт) или `MANUAL` (исключил администратор — вернуть можно вручную).
- **Снятый кандидат не «исчезает».** Если администратор снял строку в preview, она не считается отсутствующей в перечне: ошибка распознавания одной строки не архивирует существующую олимпиаду.
- **Картинок две.** `preview_image` показывается в карточках каталога, `image` — на странице сущности; если одно поле не заполнено, интерфейс берёт второе.
- **Документы — двух видов, отдельной сущности «Источник» нет.** Перечень РСОШ (`RSOSH_LIST`) загружается администратором и привязывается к импорту; приказ или иное положение вуза (`UNIVERSITY_ORDER` / `OTHER`) принадлежит университету и служит основанием правила. У олимпиады по-прежнему хранится `source_doc_id`, поэтому видно, откуда взялась запись. Ссылка на оригинал — `docs.source_url`, одно поле, а не дублирующие `source_url` в разных таблицах.
- **Публичная модель минимальна.** Ответ олимпиады содержит только пользовательские поля (`id`, `name`, `description`, `official_url`, `preview_image`, `image`, `organizer`, `status`). Служебные `name_norm`, `source_doc_id`, `createdAt`, `updatedAt`, `archive_reason` наружу не выходят.
- **Краткое название — главное.** В карточках, каталоге и заголовках страниц сначала идёт краткое название (`МФТИ`), полное — уточнением под ним. Полное название нигде не прячется.
- **Отдельной сущности «организация» нет.** Организатор олимпиады — свободный текст: формулировки в перечнях разные, справочник терял бы данные.
